## 브라우저에서 확인한 기능

- 떠 있는 Network / Operating System 카드와 네 가지 Archive 링크의 실제 이동.
- 정확히 7개의 원통형 OSI 링크, 모든 계층 허브, 뒤로 가기, 키보드 Enter, 터치.
- 8개 OS 하위 영역과 모든 허브, Architecture / Topics 전환, Processes 문서까지의 이동.
- DHCP의 Lab / Research / Problem 자동 연결과 Lab → DHCP 역방향 연결.
- 정적 검색이 제목·태그에 없는 본문 단어 `MMU`도 검색하는 동작.
- 문제 해설의 초기 접힘과 키보드로 펼치기; Markdown 및 MDX 문제 페이지.
- Mermaid SVG 렌더링과 테마 변경 시 다시 렌더링.
- 코드 복사 버튼이 실제 클립보드에 필터 명령을 복사하는 동작.
- 아카이브의 검색, 주제·분류·태그·난이도·문제 유형 필터, 정렬, URL 상태 복구, 빈 결과와 초기화.
- 다크 모드 저장 및 새로 고침 유지, reduced-motion에서 float 제거.
- 대표 5개 페이지의 가로 넘침과 JavaScript 런타임 오류 없음.

홈, Network, OS, DHCP 본문, Problems 아카이브를 여러 폭에서 캡처했다. 실제 캡처를 보고 320px OSI 보조 텍스트 겹침을 수정했으며, 작은 화면은 44px 이상의 링크 영역과 계층 이름을 유지한다. 보조 키워드는 각 허브에서 볼 수 있다. 최종 캡처는 `/tmp/netos-qa/`에 있다.

## 메타데이터 및 자동 발견

단위 테스트는 중복 topicId, 없는 relatedTopicIds, 잘못된 domain/category 조합, 필수 필드 누락, 유효하지 않은 날짜, 문제별 필수 메타데이터 누락, draft 노출 및 public → draft 참조를 검사한다. 오류에는 원본 문서 경로가 포함된다. 실제 임시 파일로도 잘못된 메타데이터가 거부되는 것을 확인했다.

실제 빌드 발견 테스트는 UI를 수정하지 않고 Network 문서를 추가해 Labs 아카이브, L7 허브, OS Processes 허브, DHCP와 Processes 개념의 역방향 연결, 자체 본문 페이지를 확인했다. 별도의 임시 MDX 파일은 Mermaid JSX 변환을 검사한다. 임시 문서는 모두 제거했고 정상 9개 문서로 복구했다.

## 수정한 초기 실패

초기 검사에서 발견한 호환성 및 QA 문제는 수정 후 다시 검사했다.

- Astro 7의 Markdown processor를 공식 `unified()` API로 구성.
- 최신 Starlight의 sidebar `items` 안에 autogenerate 설정 배치.
- MDX와 Expressive Code 중복/순서 문제 해결; Starlight가 지원되는 통합을 구성하도록 정리.
- `tsx` CLI의 제한된 IPC 소켓 대신 `node --import tsx` 사용.
- 에이전트 환경에서 Astro가 미리보기를 자동 백그라운드화하는 동작을 고려해 Playwright에 전용 포트와 `--ignore-lock` 설정.
- 테스트의 모호한 제목 선택자 및 select label 선택자 수정.
- 떠 있는 카드는 실제 포인터/터치 입력으로 검사하고 hover 정지 동작을 유지.
- Starlight의 `disable404Route` 설정으로 사용자 정의 404와의 경로 중복 제거.
- Markdown의 raw HTML과 MDX의 JSX AST를 구분해 Mermaid 처리.

최종 검사에 실패한 테스트는 없다.

## 남은 경고 및 검증 범위

Mermaid의 선택적 다이어그램 청크 일부가 500kB를 초과해 Vite의 청크 크기 경고가 남는다. Mermaid는 다이어그램이 있는 본문에서만 동적으로 불러오며, 홈과 탐색 화면에서는 요청하지 않는다. 이 경고는 빌드 실패가 아니며 실제 다이어그램 동작을 검사했다.

브라우저 자동화는 Chromium과 터치 에뮬레이션으로 수행했다. 실물 iPhone, Safari, Firefox 및 GitHub Actions의 실제 원격 실행은 수행하지 않았다. 로컬 검증 환경은 macOS / Node 25.6.0이며, 문서와 CI는 Node 24 LTS를 사용하도록 구성되어 있다.

## Git 및 배포 상태

- 로컬 Git 저장소를 `main`으로 초기화했다.
- 커밋과 원격 저장소 연결, push, 실제 GitHub Pages 배포는 수행하지 않았다.
- `.github/workflows/deploy.yml`은 `main` push 및 수동 실행을 지원한다.
- 공식 Astro 액션과 Pages 액션을 사용한다. 잠금 파일 변경을 거부하고 `npm ci` 후 타입·내용·단위·출력·브라우저 검증에 모두 성공해야 배포한다.
- 저장소명에 따른 site/base 계산과 사용자 사이트·사용자 도메인 재정의를 준비했다.

남은 수동 단계는 GitHub 저장소를 선택해 소스를 커밋/push하고, **Settings → Pages → Source: GitHub Actions**를 설정하는 것이다. 이후 Markdown 수정도 동일한 워크플로로 배포된다. 커스텀 도메인을 사용할 때만 README에 안내한 추가 변수를 설정한다.

## 후속 UI 개선 검증 — 2026-10-24

- Previous / Next 탐색의 시스템 글꼴, 글자 크기와 굵기를 본문 디자인에 맞춰 정리했다.
- Connected knowledge의 분류 제목과 카드 사이를 1.1rem 이상으로 분리했다. 실제 브라우저에서 16px 이상의 간격을 확인했다.
- 문단 바로가기 아이콘의 간격 변수를 수정하고 제목·래퍼의 크기를 맞췄다. 실제 텍스트 끝에서 아이콘까지 8px 이상의 간격을 검사했다.
- Starlight의 현재 섹션 감지와 aria-current를 유지하면서 활성 목차 글자가 1.1배 확대되게 했다. 스크롤로 다른 섹션에 도달하면 이전 항목은 원래 크기로 돌아온다. 데스크톱과 모바일에서 실제 스크롤로 검사했다.
- 기본 select 동작을 유지하며 드롭다운 화살표를 오른쪽에서 0.9rem 안쪽으로 배치했다.
- 공통 푸터에 GitHub / Email 자리를 추가했다. 주소는 `src/config/contact.ts`에서 설정한다. 미설정 상태는 링크가 아닌 라벨로 표시한다.
- `astro.config.mjs`에서 프로젝트 개발 도구 모음을 비활성화했다. 개발 서버의 실제 DOM에 `astro-dev-toolbar`가 없음을 확인했다.
- `sourceUrl` 메타데이터와 클릭 가능한 원문 출처 표시를 추가했다. HTTP(S) 원문 주소 검증과 잘못된 주소 거부를 검사했다.
- `templates/작성양식/`에 4종 작성 양식과 GitHub 웹 게시 안내를 추가했다. 양식의 메타데이터는 유효하며 공개 컬렉션에는 들어가지 않는다.
- 새 검증 후 타입 검사 오류·경고·힌트 0, 단위 테스트 13/13, 브라우저 테스트는 기본 경로 및 `/NetOS` 각각 22/22 통과했다.
- 32개 페이지의 내부 링크·자산·앵커 1,069건을 두 경로에서 검사했다. 개발 화면 캡처는 `/tmp/netos-refinements/`에 있다. 브라우저 런타임 오류는 없었다.

GitHub에서 `main`에 커밋하면 배포된 사이트가 갱신되는 워크플로는 이미 구성되어 있다. 아직 원격 저장소와 Pages를 연결하지 않았으므로 실제 배포는 수행하지 않았다. GitHub에서 수정한 커밋을 로컬 개발 화면에도 반영하려면 `git pull`이 필요하다. 기존에 실행 중이던 사용자 개발 서버는 종료하지 않았다.

## 작성양식 개선본 검토 — 2026-10-24

`templates/작성양식- 개선버전/`을 기존 양식과 비교했다. 실험의 미수행 상태·재현 조건, 연구의 경쟁 가설·반례, 문제의 오답 분석 안내가 더 구체적이므로 기본 `templates/작성양식/`에 채택했다. 비교용 개선버전 원본은 보존했다. 기존 화면·컴포넌트·스타일·메타데이터 스키마는 수정하지 않았다.

실제 빌드에서 발견한 오류는 두 가지였다.

- MDX 예시의 `import { url }`이 Astro가 자동 생성하는 `url` export와 충돌했다. 기본 작성 가이드 및 프로젝트 README를 `import { url as assetUrl }`로 수정했다.
- 개념 양식의 HTML 주석은 확장자를 `.mdx`로 바꾸면 파싱 오류를 냈다. 이미 본문에 설명된 자동 연결 안내를 반복하는 주석만 제거했다.

가이드에는 실제 draft 제외 범위, 초안에도 적용되는 참조 검증, 공개 글 → 초안 개념 참조 거부, 폴더 깊이에 따른 MDX import 경로, HTTP(S) 출처 주소, public 첨부파일의 공개 범위를 명확히 적었다. 문제의 접기 구조는 현재 Markdown·MDX 파이프라인에서 정상 동작하므로 유지했다. 정답 검색 제외는 [Pagefind의 제외 속성](https://pagefind.app/docs/indexing/#removing-individual-elements-from-the-index)과 생성된 검색 인덱스를 확인했다.

## 구조 및 README 정리 — 2026-10-24

- 테스트를 `tests/unit/`, `tests/browser/`, `tests/integration/`, `tests/visual/`로 구분하고 import 및 npm 실행 경로를 갱신했다. 기존 검사는 삭제하지 않았다.

정리 후 실제 검증 결과는 타입 오류·경고·힌트 0, 단위 15/15, 전체 브라우저 22/22 통과다. `npm run test:discovery`와 `/NetOS`에서 `npm run test:templates`도 이동한 경로에서 성공했다. 최종 `npm run qa`는 32페이지를 빌드하고 내부 링크·자산·앵커 1,069건을 검사한 뒤 전체 성공했다.

앱·샘플 글·정적 자산·잠금 파일 44개의 작업 전후 SHA-256을 비교해 모두 보존됐음을 확인했다. 새 안내 문서의 로컬 링크 41건과 수동 캡처 스크립트 두 개의 문법도 확인했다. 수동 화면 캡처 자체는 이번 구조 정리에서 재실행하지 않았다. 임시 문서·첨부파일은 모두 정리했고 정상 루트 빌드를 복원했다. Git 스테이징·커밋·push는 수행하지 않았다.
